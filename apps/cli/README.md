# @cortex/cli

The terminal app: an [Ink](https://github.com/vadimdemedes/ink) UI over `@cortex/agent`, and the **composition root** — `src/runtime/bootstrap.ts` is the one place that knows every package and wires them together. Everything else here is small and single-purpose.

## Running

```
npm run dev                          # full-screen UI (needs a real terminal)
npm run dev -- --mode plan           # start in a permission mode
npm run dev -- --agent scan          # start as an agent: scan | suggest | fix
npm run dev -- -p "explain src/a.ts" # one shot: answer on stdout, tool calls on stderr
npm run build                        # bundle the installable package into dist/ (see build.mjs)
```

Configuration comes from the environment or a `.env` in the working directory; see the root `.env.example` and README. In `-p` runs nobody can approve a call, so anything that needs approval is refused (with a hint) unless `--mode` or an allow rule covers it. To try it as a command from source, `npm link` in this folder (`bin.cortex` runs `src/index.ts` through `tsx`); users install the bundled package from `dist/` instead.

With nothing configured the UI still opens, and tells you to run `/provider` to enter an API key and model (see the root README for where they are saved). In the UI: `/help`, `/clear`, `/mode`, `/provider`, `/model`, `/theme`, `/quit`; `enter` sends, `shift+enter` (or `\` then `enter`) starts a new line, `ctrl`/`alt` + `←` `→` (or `alt+b` / `alt+f`) move by word, `home` / `end` (or `ctrl+a` / `ctrl+e`) go to the start and end of the line, `ctrl+w` / `alt+backspace` delete a word, `ctrl+u` / `ctrl+k` delete to the start / end of the line, `↑` `↓` move between the lines of a multi-line entry and past its first or last line recall earlier messages, a paste keeps its line breaks, `@` and a few letters opens a menu of the workspace's files (`↑` `↓` choose, `tab` fills in the path, `enter` does too once a letter is typed, `esc` closes it; the path is typed plain, without the `@`, because that is what the agent's context provider attaches to the turn), `page up` / `page down` scroll the transcript (a row at the bottom says how far back you are; it works while the agent is busy or asking, and sending a message returns to the end), `ctrl+r` searches the earlier messages (type to narrow, `ctrl+r` or `↑` for an older match, `↓` for a newer one, `enter` or `tab` loads the match into the box to edit, never sends it, `esc` gives up; it does not open while `/provider` asks for a key), `shift+tab` cycles the permission mode, `esc` interrupts (a real `AbortSignal` down to the HTTP request), `ctrl+t` expands the last tool call, `ctrl+c` quits. When the agent needs approval a prompt takes over: `y`/`enter` allows, `n`/`esc` refuses.

## Structure

`src/` is the entry file plus five folders. Each folder is one job, and imports only flow downward (checked by `test/layering.test.ts`):

```
index.ts ─► cli/ ─► runtime/ ─► provider/        cli/ also uses format/
        └─► ui/  ─► provider/, format/           ui/ sees runtime/ for types only
```

| Folder | Job | Files |
| --- | --- | --- |
| `index.ts` | the entry: parse flags, load `.env`, bootstrap, then render the UI or run one shot | |
| `cli/` | how the process is driven from the command line | `args.ts` (flags), `env.ts` (`.env` loading; real environment variables win), `run-once.ts` (the `-p` path: only the final answer goes to stdout; tool calls and what the model said on the way to them go to stderr, and text is not streamed because a piped answer is only known to be the answer once no tool call follows it), `version.ts` (the version shown in the header), `git-branch.ts` (the branch, read from `.git/HEAD` rather than by running git: one small file read, no git needed, cannot hang; follows worktree pointers, shows a short hash when detached) |
| `runtime/` | building the agent stack, and the seam to the UI | `bootstrap.ts` (the composition root: registers providers, tools and context providers; loads settings, memory, skills and MCP servers; builds the shared `AgentPolicy` and sessions), `permission-bridge.ts` (how the agent's approval request reaches the UI and back), `workspace-files.ts` (the file list behind the `@` menu, from `@cortex/context`'s walker, handed to the UI by `index.ts`) |
| `provider/` | choosing and configuring the LLM provider; no React, no Ink | `config.ts` (picks the provider and resolves its config from the environment, with saved settings layered underneath; empty values count as unset), `manager.ts` (the running app's provider: a delegating client, what is saved, and `configure` / `remove` that save and switch without a restart; nothing it returns contains a key), `setup.ts` (the `/provider` questions and the pure state machine that walks them) |
| `format/` | how tool calls and markdown are described; shared by `cli/` and `ui/` | `tool-calls.ts` (summaries from each tool's own `summarize`, the tool's own `preview` fetched before it runs, status of a result, durations, result text, failure detection), `path.ts` (home as `~`, a folder cut from its start so its end survives), `status.ts` (which footer parts fit at a given width: model, context, branch, folder, most important first), `counts.ts` (a rough token count in short form, `340` / `1.2k`), `file-mentions.ts` (`@file` completion as pure functions: the `@word` at the cursor, ranking files by exact name, name prefix, name, path, then letters in order, and splicing the chosen path in), `diff.ts` (a line diff with line numbers: trims what the texts share, LCS on the changed middle, caps its work, collapses far-away unchanged lines into gaps), `markdown.ts` (block parser: headings, nested/ordered/task lists, quotes, fenced code, tables, rules; tolerant of text still streaming in), `inline.ts` (bold, italic, strike, code, links and bare URLs as styled runs), `table.ts` (column fitting, cell wrapping, box borders and display width, as pure functions), `highlight.ts` (code to lines of scoped runs through `lowlight`; no language guessing) |
| `ui/` | everything that draws the screen or handles keys | `App.tsx` (composes the screen, handles keys), `commands.ts` (slash commands, pure logic over a `CommandHost`), `layout.ts` (rows left for the transcript), `types.ts` (transcript entries) |
| `ui/theme/` | colors and words, in one place | `themes.ts` (semantic color tokens and the `dark` / `light` / `mono` themes; `NO_COLOR` forces mono), `ThemeContext.ts` (`useTheme()`; components never hardcode a color), `copy.ts` (taglines, hints, tips, fixed sizes). The palette is deliberately quiet: two soft brand colors (`primary` dusty blue, `secondary` sage), neutral greys (`muted`, `border`, and a lifted `inputBackground`), and `status` / `diff` / `syntax` colors drawn from the same hues. The theme tests enforce WCAG AA contrast for every text color and keep every coloured token below 60% saturation (the brand colors below 50%), so a future tweak cannot drift back to neon |
| `ui/logo/` | the emblem and the wordmark | `emblem-art.ts` (**generated**: the logo as braille, 8 dots per cell), `emblem-layout.ts` (picks large / medium / wordmark-only by terminal size), `Emblem.tsx` (draws it in the primary color), `pixel-logo.ts` (the CORTEX wordmark: a 5x7 bitmap font packed two pixels per cell with half-blocks, in three widths), `Logo.tsx` (draws the wordmark in the primary color) |
| `ui/toolcalls/` | tool calls in the transcript and the approval prompt | `ToolCall.tsx` (a header with status glyph, `+3 -1` and duration, then an edit's diff, a command's output, or why a call did not go through), `Preview.tsx` (draws a diff with line numbers, signs, background bands and syntax colors, or a command; can pin every line to one row), `preview-model.ts` (pure: the cached diff, change counts, and the exact row count a preview takes) |
| `ui/markdown/` | drawing markdown | `Markdown.tsx` (block layout: headings, hanging-indent lists, quotes, rules, spacing; finished blocks never re-render while a later one streams), `CodeBlock.tsx` (light bracket and theme syntax colors), `Table.tsx` (boxed, fitted to the width), `Inline.tsx` (styled runs, links with their URL) |
| `ui/components/` | the pieces on screen | `Banner`, `InputBox` (a rule above and below with a lifted band between, a grey `>` and a block cursor, a dimmed `Try "…"` example when empty; can mask a secret), `StatusLine` (`? for shortcuts`, or the permission mode when it is not the default, on the left; on the right as many as fit of the model, how full the context is (amber from 75%, rose from 90%), the folder and the git branch; always one row, the optional hint going before the model name is cut), `ThinkingIndicator` (spinner, verb, elapsed time and, while text streams in, `↓ 1.2k tokens`; always one row, giving up its details from the least important), and consistent icons: `✗` for a model failure and `·` for a notice, in a two-column gutter, `Messages` (messages, tool calls, notices, and the viewport: scrolling is a negative bottom margin on the transcript's column, limited by its measured height, plus a one-row "↓ N rows below" notice while scrolled), `Overlay` (draws a menu or prompt over the bottom of the transcript instead of making room for it, so opening one moves nothing; the caller passes the exact row count), `Prompts` (the approval prompt and the `/provider` question), `SlashCommandMenu` (also the provider picker and the `@` file list; every item is one row, long paths are cut from their start), `HistorySearchLine` (the one-row ctrl+r line above the box: the query, which match this is, key hints that drop first on a narrow terminal), `ThinkingIndicator` |
| `ui/hooks/` | state behind the components | `useChat` (transcript, cancel, expanded tool calls, one live assistant message that grows as text streams in (first piece at once, the rest batched every 50 ms, replaced by the exact final text; an interrupted reply keeps what was written), and each tool call's life: preview taken before it runs, awaiting approval, then success, error, declined or interrupted), `useTextInput` (input state, with the pure text-editing functions beside it: word and line movement and deletion, moving between lines, backslash-enter, paste clean-up), `keys` (the editing keymap as a pure `editFor(typed, key)`, and Home/End, which Ink's `useInput` does not report, read from the raw sequence), `useInputHistory` (up/down recall, and the pure pieces of ctrl+r: `historyMatches` and the `stepHistorySearch` key reducer; the messages come from earlier sessions through `index.ts`, which loads and saves them with `@cortex/config`), `useTranscriptScroll` (how far the transcript is scrolled, as rows from the bottom, in pure functions: the offset stays on the same text while new rows arrive, and never passes what there is to scroll to), `useWorkspaceFiles` (the `@` menu's file list: read the first time an `@` is typed and again after a turn, never at startup; the lister is passed in), `useGitBranch` (the branch, read at startup and after each turn; the reader is passed in so the UI never touches the file system), `useProviderSetup` (drives the `/provider` flow), `terminal` (alt screen, and the terminal's size: `App` listens for resizes once and shares the size through `TerminalSizeContext`, because every listener is one more on the real stdout and Node warns, onto the screen, past ten), `animation` (spinner, verb, elapsed time) |

`emblem-art.ts` comes from the logo image through `tools/make-logo.mjs` (`node apps/cli/tools/make-logo.mjs logo.png`, or `--preview` to see the dot grids first). It finds the bright strokes, fits the shape into a grid of braille dots (2x4 per cell, so a line can be a dot thick), and lights a dot when enough of its patch of the image is stroke. Re-run it only when the logo changes; nothing at runtime reads an image, and the tool decodes the PNG with `node:zlib`, so it needs no dependency.

Tests mirror `src/`: `test/<folder>/<file>.test.ts` (the text-editing functions are tested in `test/ui/hooks/useTextInput.test.ts`). Component tests (`*.test.tsx`) render through Ink into a fake terminal with `test/ui/support/render-frame.tsx` and assert on the plain-text frame. `test/ui/app.test.tsx` drives the whole `App` with `test/ui/support/drive-app.tsx`: a fake terminal and keyboard, a stand-in agent session and provider manager that record what they are given. It types, presses keys and reads the screen, and it is where the keys, the `@` menu, ctrl+r and the rule that an API key never reaches the history, the screen or the agent are proved.

The full-screen layout is a fixed-height column: a bottom-anchored transcript (clipped by `overflow="hidden"`, so the newest content stays visible; its inner column must have `flexShrink={0}`, or Yoga squeezes it to fit and the screen shows the start of the conversation, overlapped, instead of the end), the thinking line or approval prompt, the slash menu when open, the input box, and the status line (model, mode, directory).

Tests: `npm test -w @cortex/cli`. The UI components are covered through the pure modules they use (layout, text editing, commands, formatting); the interactive screen needs a real terminal and is exercised by hand and by `npm run test:e2e:cli` against a live model.
